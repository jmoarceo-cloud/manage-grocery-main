# groceryone-docs-progress

Read [project context](../../../.ai/project-context.md) for the canonical scope, progress and evidence paths. Inspect the actual changed artifacts and verification output before editing status.

- Identify the document that owns each changed fact. Update that authority, then affected links and summaries; avoid creating a second master backlog.
- Separate source statements, design intent, implemented behavior, executed checks and unresolved questions. Documentation completion is not software completion.
- Record the dated task, actual changed files, exact meaningful checks, failures/skips, limits and next authorized action in the project's existing progress owner.
- Preserve historical decisions and archives with dated corrections. Never resume an archived handoff as a current instruction.
- Check new/changed local links, skill references and requirement IDs. For AI tooling, distinguish parsed configuration, protocol discovery and native-client activation.
- Do not claim a thesis study, adviser review, deployment or runtime test occurred unless actual evidence supports it.

For AcademiSync, follow the existing documentation maintenance policy and active roadmap; for GroceryOne, HCI_SYSTEM owns behavior while docs/PROGRESS owns maintenance outcomes; for HROMS, retain the application documentation-only phase until changed by the user. Use only the branch corresponding to this project (groceryone).
